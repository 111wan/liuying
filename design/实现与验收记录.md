# 留影 0.1 · 实现与验收记录

日期：2026-09-27。环境：本机 macOS / Python 3.12 / Node 24 / Chrome。

## 本次交付

实际 Web 应用，不替换或删除之前的研究资料与交互原型。

- 前端：React + TypeScript + Vite；下载、任务、平台页面；原生系统字体；白 / `#f5f5f7` / `#1d1d1f` / `#0071e3`。无外部字体或分析脚本请求。
- 后端：FastAPI；SQLite；有界后台调度器；每个解析/下载任务在独立进程执行。另提供 PostgreSQL + Redis + Celery 配置，但容器运行尚未验收。
- 文件：真实 HTTP 数据流、最多两路音视频合并、容器识别、时长与大小限制、前 2 秒解码检查。这个检查不是对整条视频逐帧完好性的保证。
- 安全：链接域名精确识别、私网地址拒绝、逐跳检查、连接前 DNS 解析与校验、禁用 yt-dlp 原生 curl 处理器、FFmpeg 只读本地文件且限制容器格式、会话绑定、CSRF、签名文件票据、Host 白名单。

## 接入边界

快手、小红书、Evil0ctal 返回数据的适配器有离线合同测试。其他平台经 yt-dlp 返回可下载的直连格式；没有可用格式时明确失败，不伪造无水印链接。所有未完成真实作品验收的平台，页面标注「已接入 · 待实测」。

小红书缺少完整 token 或需要登录、抖音要求有效 Cookie / 签名、海外平台网络或访问限制，都会影响实际结果；不能从公开直链样片的成功推出这些平台同样可用。Evil0ctal 服务没有自动部署，用户 Cookie 没有读取或导入。

实际发现并修正：样片站点拒绝默认浏览器样式 User-Agent（403），公开视频直链改为明确的应用 User-Agent，随后真实 HEAD/GET 与浏览器保存均通过。对源站限制不做隐藏式重试或自动验证码处理。
