## 2. 分项目详析

### 2.1 JoeanAmier/TikTokDownloader(拟改名 DouK-Downloader)

**元数据**:16,324★ / GPL-3.0 / JavaScript+Python / 最后 push 2026-09-22 / 41 个 open issue / 有 Discord。

**技术原理**(基于 master 源码与 docs/DouK-Downloader文档.md):
1. **短链还原**:支持 `v.douyin.com/`、`vm.tiktok.com`、`vt.tiktok.com` 及整段分享文案(自动正则抠链接);跟随重定向取得真实 URL 与作品 ID。
2. **无水印地址**:详情接口返回 JSON 后,取 `video.bit_rate[].play_addr.url_list` 按码率排序取最高档直链(即平台已发布的"无水印流",源码 `src/extract/extractor.py` L500-551);不做 playwm 替换、不去水印。`download_addr`(烧录水印的下载地址)不用。
3. **签名机制(2026 现状,重要变化)**:历史版本自带 X-Bogus/a_bogus/msToken 实现(`src/encrypt/` 下 xBogus.py、aBogus.py、msToken.py、douyin_params.py、websign.py,及 `static/js/` 下 X-Bogus.js、a_bogus.js、webmssdk.es5.js、sdk-glue.js、runtime_bundler_34.js)。其中 douyin_params.py 头部声明其 a_bogus/webSign 实现**移植自 Evil0ctal v5 的原生逆向**(bdms.js v1.0.1.19-fix.01、secsdk runtime_bundler_34.js / @byted/secsdk-strategy v1.0.40)。msToken 走 `mssdk.bytedance.com/web/common`(magic=538969122 协议),ttwid 走注册接口。
4. **合规让步(关键)**:文档明确"**为确保项目合法合规,本项目的加密参数算法不再维护**;如因平台更新导致部分功能无法正常使用,请自行准备加密参数生成代码"。现提供 `encipher.py` 插件机制(继承 `Params` 基类实现 `sign`/`sign_url`,可内嵌 JS 执行或调用第三方签名 API),6.0 版本将整体重构出 GUI/WebUI。
5. **设备伪装**:请求层已从 httpx 切换为 **curl_cffi**(浏览器 TLS 指纹模拟),支持代理;Cookie 需用户手动配置(浏览器读取功能已移除)。

**难点应对**:抖音签名保护接口清单直接写在代码注释里(如 `/aweme/v1/web/aweme/detail/` 受保护,实测 2026-09-08 无完整签名时 8 次仅 3 次成功、其余 403 "Uifid Not Found")。

**优点**:功能最全(视频/图集/实况/直播拉流/评论/合集/搜索);持续高频修复(Release Notes 显示随 TikTok 新增 X-Gnarly 参数等)。
**缺点/风险**:签名维护转嫁给用户(平台改版即功能失效,需用户自备签名代码或第三方 API);GPL-3.0 传染性;依赖 Cookie。
**失效案例**:issue #578"功能异常"、#600"搜索结果为空"(2026 年内),社区博客(ifmo.cn 2026-08)称其砍掉 Web UI、NAS 无人值守不便。

### 2.2 Johnserf-Seed/f2

**元数据**:2,661★ / Apache-2.0 / Python / 最后 push 2026-09-26(当日) / 72 open issue / 文档站 f2.wiki。

**技术原理**(README + 源码):
1. **平台范围**:抖音、TikTok、微博、Twitter、Bark;B站/网易云音乐在 0.0.1.8 计划中。**无小红书/快手/西瓜**。
2. **签名全自研纯 Python**:`f2/utils/crypto/bytedance/` 下 `xbogus.py`、`abogus.py`(X-Bogus 与 a_bogus 原生实现,配置项 `encryption: ab/xb` 二选一);`TokenManager` 提供 `gen_real_msToken` / `gen_false_msToken`(126 位随机形状伪装)/ `gen_ttwid` / `gen_webid`;`VerifyFpManager` 生成 verify_fp、s_v_web_id;直播另有 `webcast_signature.js`(JS 执行)。README 功能表逐接口标注了签名/Token 工具类。
3. **短链还原**:`AwemeIdFetcher` 系列正则提取 aweme_id;测试用例显示输入为 `iesdouyin.com/share/video/{id}?...` 全参数分享链,请求走 `www.douyin.com/aweme/v1/web/...` 系列接口,短链先重定向再提 ID。
4. **下载**:httpx 异步;m3u8 依赖(pyproject);无浏览器依赖(纯 HTTP)。

**优点**:Apache-2.0 可商用;无浏览器/无 cookie 也能下公开作品(登录态用于私密内容);API+CLI 形态适合服务化;作者活跃(2026-09-26 仍提交)。
**缺点/风险**:覆盖平台少(对"全平台站"贡献有限);纯自研签名维护成本高(平台一改算法需作者更新);无身份池/风控调度(单 cookie 直连,批量易被限)。
**风险证据**:README 明示"生成的假 msToken 与真 msToken 形状一致"——一旦抖音服务端加强校验,假 token 通道会整体失效(未核实现状)。

### 2.3 NanmiCoder/MediaCrawler

**元数据**:65,761★ / License "Other"(NCAL 1.1,自定义、非 OSI;README 声明"仅供学习,禁止商用")/ Python / 最后 push 2026-09-19 / 210 open issue / 12.7k fork。

**技术原理**(README + 源码 + 2026-06 腾讯云社区深度分析文):
1. **定位**:爬虫(内容+评论)而非下载器,但自带 `media_downloader`(小红书/抖音/快手/B站/微博媒体下载)。**B 站为 DASH 合流产物**(`fnval=DASH_FNVAL` 取音视频分轨,ffmpeg 合流;BILI_QN 默认 80=1080p,权限不足自动降档)。
2. **反检测核心:CDP 模式默认开启**——`playwright.connect_over_cdp` 连**用户真实 Chrome**(复用登录态/Cookie/扩展,绕开 navigator.webdriver),或自动启动并注入 stealth.min.js + 反检测 flag。
3. **各平台签名策略(代码级确认)**:
   - **小红书**:纯算签名——`xhshow` 库 + `playwright_sign.py` 的 `sign_with_xhshow()` 生成 `x-s`/`x-t`/`x-s-common`/`x-b3-traceid`,启动时 monkey-patch 修复第三方库 bug;`help.py` 内还 vendored 一份经典 x-s/x-t 算法。
   - **抖音**:在 playwright 页面上下文里执行 JS 生成 **a_bogus**(注释"20240927 a-bogus update (JS version)"),配合浏览器 localStorage/cookie 直连 web API;需要 Node.js。
   - **快手**:REST v2 接口加 **`__NS_hxfalcon` 签名参数,由 playwright 页面内 JS 生成**(`get_ks_sign_from_playwright`),另有 GraphQL 通道(`www.kuaishou.com/graphql`)。
   - **B站**:wbi 签名(`BilibiliSign`),wbi 密钥从 localStorage `wbi_img_urls` 或 nav 接口获取。
4. **登录**:各平台扫码登录保存登录态(qrcode);代理池、SQLite/MySQL/CSV/JSON 存储。
5. **商业化**:README 广告位(TikHub 签名 API 联运 + Atlas Cloud);MediaCrawlerPro 付费订阅;作者一人占约 78% commit,无 CI、0 平台核心单测。

**优点**:覆盖最广(7 平台)、社区最大、教学文档全;CDP 思路绕开大部分指纹风控;抖音/快手签名靠浏览器"白嫖"真实算法,作者无需逆向。
**缺点/风险**:自定义 NCAL 许可+禁止商用(对"我们的网站"是硬伤);依赖用户真机浏览器/登录态,不适合纯服务端;单人维护;签名库/平台改版需持续 monkey-patch(文章点明"维护成本指数增长")。
**失效证据**:issue #895(account blocked,已解决)、#881(cookie 过长);文档警告小红书自动滚动会被风控。

### 2.4 JoeanAmier/XHS-Downloader

**元数据**:12,840★ / GPL-3.0 / JavaScript+Python / 最后 push 2026-09-20 / 23 open issue。

**技术原理**(源码级确认):
1. **路线:完全不做 API 签名**——全仓无 `x-s`/`x-t` 生成代码。用 **curl_cffi(浏览器指纹模拟)+ Cookie** 直接请求**网页 HTML**(`www.xiaohongshu.com/explore/{noteId}`、`/discovery/item/{id}`、`xhslink.com` 短链重定向),用 lxml 抽取 `<script>` 里的 **`window.__INITIAL_STATE__`** JSON(`noteDetailMap` 等,`source/expansion/converter.py`),从中取作品数据。
2. **无水印视频**:优先 `video.consumer.originVideoKey` → `https://sns-video-bd.xhscdn.com/{originVideoKey}`(官方原片直链,无水印);降级 `video.media.stream.{h264/h265/av1}.{分辨率}.masterUrl/backupUrls` 按分辨率/码率/大小排序取最高(该列表可能是带水印流)。**未配置 Cookie 时只能拿到低分辨率文件**(README 明示)。
3. **无水印图片**:`imageList[].urlDefault` 取 token 去掉 `!xxx` 后缀 → `sns-img-bd.xhscdn.com/{token}` 原图,或用 `ci.xiaohongshu.com/{token}?imageView2/format/xxx` 转换格式。
4. **辅助**:livePhoto 下载、断点续传、剪贴板监听、API 模式 + MCP 模式 + 油猴脚本(提取推荐/主页/收藏/点赞链接)。
5. **风控说明**:旧日期链接可能被风控需用最新链接;自动滚动页面可能触发风控/封号(脚本默认关闭)。

**优点**:签名零维护(平台改 x-s/x-t 算法不影响它);小红书功能最全;Docker/GUI/TUI/CLI/API/MCP 全形态。
**缺点/风险**:依赖 Cookie(web_session/a1,虽无需登录);SSR 页面结构一改(如抖音 `_ROUTER_DATA` 式改版)解析即断;无 Cookie 只能下低清;GPL-3.0;代码中未找到对 `xsec_token` 的专门处理(分享链接带 token 时主要依赖重定向后 URL 携带,细节未核实)。
**失效证据**:issue #325"小红书无水印视频拿不到了"(存在此类反复)。

### 2.6 Evil0ctal/Douyin_TikTok_Download_API

**元数据**:20,343★ / Apache-2.0 / Python / 最后 push 2026-09-23 / 仅 1 个 open issue / 官网 douyin.wtf(v5.0.3,4 年维护,164k Docker pulls)。

**技术原理**(官网 FAQ + 源码确认,这是本批项目中**工程化最深**的一个):
1. **覆盖**:v5 仅 `douyin`+`tiktok`(Platform 枚举就这两个);官方 FAQ 承认 v4 曾支持 B 站、v5 主动放弃,快手/小红书/微博从未支持。
2. **短链解析**:`worker/parsing.py` 手动**逐跳跟随重定向**(`follow_redirects=False` + 读 Location,`max_hops=MAX_REDIRECTS`),**每一跳落地前先过 `security.url_allowlist` 白名单**(防 SSRF/钓鱼域);短链展开走**独立代理出口**,不消耗身份池信誉。落地后按 URL 类型路由到 `aweme/detail`、`aweme/post`、`mix` 等端点。
3. **签名:纯 Python 原生实现**(`src/dtk/signing/native/`):`abogus.py`(逆向抖音 bdms.js)、`websign.py`(逆向 secsdk runtime_bundler_34.js 的 webSignUrl,产出 `uifid`+`timestamp`+`x-secsdk-web-signature`)、`xbogus.py`、`sm3.py`、`tiktok_sign.py`(逆向 TikTok webmssdk 2.0.0.561,产出 X-Gnarly/X-Dynosaur)、`tokens.py`(gen_real_ms_token 走 mssdk.bytedance.com、gen_ttwid、gen_odin_tt、以及"形状仿真"假 msToken)。签名微秒级出签;**浏览器只作兜底与"漂移探测器"**(检测平台算法变更)。
4. **身份池/风控调度**:无头浏览器定时铸造**游客身份**(让平台自己发 ttwid 等 cookie,记录真实指纹);身份池自检/降温/轮换(LRU)、每身份单请求锁、每(身份,端点)令牌桶(如 content_detail 单身份 1req/3.3s)、风控响应指数退避冷却(60s→6h 封顶)、端点级熔断器。Cookie 用 AES-256-GCM 加密存储。传输层用 **wreq**(Rust,TLS 指纹模拟)。
5. **无水印原则(官方原话)**:不做"去水印",而是"**选择平台已经发布的干净流**"——`play_addr` 优先为无水印主轨,`download_addr`(烧录水印)保留但打 `watermark: true` 标记,不按码率重排以免选到带水印大文件。CDN 直链签名会过期,归档 600s 后重解析。
6. **架构**:docker compose 一键(REST 93 操作 + MCP server + CLI + React 控制台 + PostgreSQL 归档 + Redis)。

**优点**:Apache-2.0;自托管无配额;对"做网站后端"最友好的形态(REST API/异步任务模型);风控治理最系统(身份池+熔断+健康分);抖音/TikTok 双平台签名原生实现且带浏览器漂移检测。
**缺点/风险**:不含小红书/快手/B站(与我们目标平台集合不重叠);部署重(镜像 ~4.5GB、带浏览器 6.3GB、browser 容器吃 2.5GB+ 内存);签名算法仍是猫鼠游戏(其 docs 自己承认靠浏览器探测漂移)。
**社区旁证**:ifmo.cn(2026-08)称其 v4 阶段"作者 2025-10 停更、抖音 anti-bot 拦截后失效"——虽与仓库现行 push 记录(2026-09-23)矛盾,但印证了**工具"保质期"现象与用户感知**。

### 2.7 其他值得注意的项目(简述)

- **jiji262/douyin-downloader**(12.1k★,MIT,Python,2026-09-23 仍提交):单平台抖音下载器,视频/图集/主页批量/合集/音乐,REST API,无水印优先自动选最高画质,SQLite 去重;2026-08 社区文章实测"20/20 全成功"。是服务化抖音下载的高性价比参照。
- **putyy/res-downloader**(20.2k★,Apache-2.0,Go):**不是链接解析器,而是 MITM 代理抓包器**——装 CA 证书、开系统代理,用户在自己手机/浏览器播放目标内容,工具嗅探 CDN 直链下载(README 自述"与 Fiddler/Charles 原理类似")。全仓无 douyin/xhs/kuaishou 解析代码(grep 无结果)。对"贴链接解析"场景不适用,但适合个人/桌面工具。
- **5ime/video_spider**(3.0k★,AGPL-3.0,PHP):新分支 DouyinParser 做法=请求 `iesdouyin.com/share/video/{id}` → 正则 `window._ROUTER_DATA` → `play_addr.uri` → 拼 `iesdouyin.com/aweme/v1/play/?video_id=...&ratio=1080p&line=0`。**零签名、零 ttwid**——正是已被 2026-08 抖音 SSR 改版淘汰的"页面解析"路线的活标本。旧 master 分支支持 26+ 平台(含快手/西瓜),已停更。
- **belingud/douyin-downloader-skill**(6★,MIT,2026-08-15):小但文档价值极高:两层降级(第 1 层 iesdouyin 分享页 `_ROUTER_DATA`;第 2 层 `www.douyin.com/aweme/v1/web/aweme/detail/` + **自动注册 ttwid**(POST `ttwid.bytedance.com/ttwid/union/register/` 拿 ticket → ixigua callback 换 ttwid cookie));指出 2026-08-12 起 iesdouyin SSR 不再返回 `_ROUTER_DATA`、detail API 无 ttwid 返回空、iesdouyin 有 ByteDance Acrawler 间歇 WAF。
- **Cialle/RedCrack**(231★,MIT,Python):小红书全站加密参数纯算逆向(xsec_token、a1、webId、web_session、x-s、x-xray-traceid 等),x-s/x-t 维护参考。
- **RedNote/Xiaohongshu-Shield-Algorithm**(25★,Apache-2.0):小红书 **APP 端** Shield 签名纯算还原(x-mini-mua/x-mini-sig,白盒 AES/MD5/RC4),说明 APP 协议更难;Web 端 x-s/x-t 才是下载工具主流。
- **mafqla/douyin-api**(111★,GPL-3.0,JS):抖音签名逆向一手文档(见 3.1)。
- **brock7/douyin_sign**(0★,Apache-2.0,JS):a_bogus/x-bogus 算法实现参考。
- **ZixueX/ZParse**(6★,Apache-2.0,PHP):26+ 平台纯 PHP 解析(含封面/音频),自述"无水印"。
- **ShanhaiCode/videoparse**(9★,MIT):前端式多平台解析,已停更(2025-03)。
- **TikHub(商业)**:一句话——抖音/TikTok/小红书等 14+ 平台付费数据 API,f2/Evil0ctal/MediaCrawler 三家都挂其广告或联运;自建解析的"兜底/对标"选项。

## 3. 各平台难点与技术现状归纳

### 3.1 抖音(难度:★★★★★,全领域风控最复杂)
- **短链**:`v.douyin.com` 短链 → 重定向到 `www.douyin.com/video/{aweme_id}` 或 `iesdouyin.com/share/video/{id}`。历史上解析分享页 `window._ROUTER_DATA` 即可(零签名),**2026-08-12 起 SSR 改版只返回壳**,该通道基本失效(belingud 实测)。
- **详情**:`www.douyin.com/aweme/v1/web/aweme/detail/?aweme_id=...`。缺 **ttwid** 直接空响应(非限速);ttwid 为 HttpOnly,浏览器 `document.cookie` 拿不到,需调 `ttwid.bytedance.com/ttwid/union/register/` 官方注册接口生成(ifmo.cn 与 belingud 代码一致)。
- **签名演进(mafqla/douyin-api docs/sign_reverse_findings.md,2026-06 实测)**:当前 web feed/detail 等接口需**"三件套"**:①`a_bogus`(bdms/webmssdk JSVMP,算法=SM3 双哈希 + RC4 固定 keystream + 自定义 base64);②`timestamp`;③`x-secsdk-web-signature`(securitySDK,确定性 128-bit,依赖 localStorage 会话密钥:ECDSA P-256 私钥、服务器证书、ticket;握手端点 security.zijieapi.com)。**三者同源校验**(cookie 与签名会话必须一致),缺一 403。旧单参数 X-Bogus 通道已被淘汰;`msToken`(mssdk.bytedance.com/web/common)与 `s_v_web_id`、`odin_tt`、`verify_fp` 仍是必备身份参数。
- **风控**:空 200(anti-bot)、iesdouyin Acrawler WAF、限速、批量封 IP/身份;短剧(playlet)接口无公开通道,社区共识只能录屏。
- **主流实现矩阵**:原生纯算=Evil0ctal v5 / f2(ab+xb)/ TikTokDownloader(移植 Evil0ctal,但算法停止维护);浏览器出签=MediaCrawler(page JS);页面解析=video_spider(已失效)、belingud 第 1 层(已失效,靠第 2 层 API 兜底)。

### 3.2 快手(难度:★★★)
- **短链**:`v.kuaishou.com/xxx`、`kuaishou.com/f/xxx` → 重定向 → `www.kuaishou.com/short-video/{photoId}` 或 `chenzhongtech.com` 分享页,提取 `photoId`(KS-Downloader 代码)。
- **详情两条路**:①`live.kuaishou.com/live_api/profile/feedbyid`(photoId+principalId,**无签名,游客 cookie 即可**)——KS-Downloader 用;②`www.kuaishou.com/rest/v2/...` + **`__NS_hxfalcon` 签名(必须由浏览器页面 JS 现场生成)**、或 GraphQL——MediaCrawler 用。
- **无水印**:接口返回里选 `mp4Url`/`photoUrl`(官方干净流);历史上 "noSig" 参数/换域名的民间技巧(未核实现状,不推荐)。
- **风控**:相对抖音温和;游客 cookie(`did`)即可,批量建议加代理。
- **项目覆盖**:KS-Downloader(专精)、MediaCrawler(爬虫+下载)、res-downloader(抓包)、video_spider 旧版。**无像 Evil0ctal 级别的"快手原生签名 API 服务"开源项目**。

### 3.3 小红书(难度:★★★★,签名易、风控诡)
- **短链**:`xhslink.com/xxx` → 重定向 → `www.xiaohongshu.com/explore/{noteId}(?xsec_token=...)`。`xsec_token` 是分享链接加密参数(RedCrack 有纯算生成)。
- **两条技术路线**:
  - **路线 A(SSR 页面解析,XHS-Downloader)**:curl_cffi 模拟 Chrome + Cookie 抓 explore 页 HTML → 解析 `window.__INITIAL_STATE__`(noteDetailMap)。**完全不需要 x-s/x-t**;代价:无 Cookie 只有低清、SSR 改版即断。
  - **路线 B(Web API + 纯算签名,MediaCrawler/RedCrack/Shield-Algorithm)**:x-s/x-t 由"url+data+ctime+cookie(a1)的 MD5 类算法"生成(可纯 Python,xhshow 库),外加 `x-s-common`、`x-b3-traceid` 等新参数;**461 状态码 + verifytype 字段**是典型风控响应(2023 年起),IP/账号级封禁常见;自动滚动等自动化行为会被检测。
- **无水印**:`video.consumer.originVideoKey` = 官方原片直链(优先);`video.media.stream.*` 各档流可能带水印;图片靠 token 去后缀拿原图(`sns-img-bd.xhscdn.com/{token}`,去掉 `!nd_...` 之类处理参数)。
- **APP 端**协议(shield、x-mini-mua)难度更高,下载工具普遍走 Web 端。

### 3.4 B站(难度:★★★)
- **ID**:短链 `b23.tv` 重定向;`BV`/`av` 号互转有公开算法。
- **详情**:`api.bilibili.com/x/web-interface/view` + **wbi 签名**(wbi_img 密钥来自 localStorage 或 nav 接口;MediaCrawler `BilibiliSign`)。
- **无水印/高清**:B 站源流本身不烧录水印,"去水印"=下载原流;难点是**DASH 音视频分离**:`x/player/wbi/playurl` 带 `fnval=4048`(DASH)取 `dash.video[]`(纯视频轨)+`dash.audio[]`(纯音频轨),**ffmpeg 合流**(MediaCrawler media.py 确认);清晰度 qn(默认 80=1080p,大会员/登录权限不足时自动降档);老接口 `fnval=0`(durl)为已合并的 flv/mp4 低清备选。
- **风险**:bilibili-API-collect 被律师函关停证明 B 站法务对 API 文档/逆向项目最主动;但 playurl 本身是公开接口,合规自用风险可控(需法务评估)。

### 3.5 西瓜视频(难度:★★,但生态最薄)
- **现状**:头部项目(f2/TikTokDownloader/Evil0ctal/MediaCrawler/KS-Downloader)**均不支持西瓜**;仅有停更的老项目(5ime/video_spider master 分支、xnnpt/-、jym66/Dlink_Parse 等 PHP 解析站)声称支持。
- **机制(基于老项目描述,参数细节未核实)**:`v.ixigua.com` 短链 → `ixigua.com/{id}` 页面(内嵌 JSON 或 `_ROUTER_DATA` 式数据,含 videoResource/playApi 字段)→ 取播放直链;字节系(与抖音同源 CDN/风控体系),正常流本身无烧录水印,难点主要是页面结构解析与偶发风控。
- **结论**:如纳入产品范围,需自研页面解析或接字节系通用签名方案,开源无成熟可直接依赖的实现。

## 4. 通用"去水印下载链路"汇总与实现差异

### 4.1 通用四段链路

```
① 短链解析            ② 详情获取                 ③ 无水印地址构造             ④ 直链下载
粘贴分享链(含文案) →  平台详情(页面/API)      →  选择官方"干净流"        →  CDN 直链
正则抠 URL       →   提取 item ID + 元数据   →  (play_addr / originVideoKey →  带 UA/Referer
HTTP 重定向跟随   →   携带身份参数            →   / mp4Url / DASH 轨)    →   断点续传/合流
(逐跳+白名单可选) →   (ttwid+msToken+签名     →  绝不"烧录后去水印"     →   直链过期需重解析
落点提 ID        →    / cookie+指纹)         →   (download_addr 弃用)   →   图片去后缀取原图
```

**各段要点(基于本次抓取的实现)**:

1. **短链解析**:两种姿势——(a) `allow_redirects=True` 一把梭(KS-Downloader/XHS-Downloader/belingud);(b) **手动逐跳 + 每跳落地前白名单校验 + 独立代理出口**(Evil0ctal v5,防 SSRF 且保护身份池信誉)。落点正则:抖音 `aweme_id`、快手 `photoId`、小红书 `noteId`、B站 `bvid`。分享文案先正则抠链再解析(f2/TikTokDownloader 均支持整段文案)。
2. **详情获取三派**:
   - **页面解析派**(SSR/HTML JSON):XHS-Downloader(`__INITIAL_STATE__`)、video_spider/belingud 第 1 层(`_ROUTER_DATA`)。零签名成本,但平台一改 SSR 就断(抖音 2026-08 已断)。
   - **API + 原生签名派**:f2、Evil0ctal v5、TikTokDownloader(旧内置)、KS-Downloader(快手接口恰无需签名)。成本=持续逆向维护(抖音 a_bogus+secsdk 三件套;小红书 x-s/x-t)。
   - **浏览器/真机环境派**:MediaCrawler(CDP 页面 JS 出签、真实登录态)、res-downloader(MITM 抓包)。零逆向成本,但需要浏览器/用户设备,不适合纯服务端。
3. **无水印地址构造——统一共识是"选流"而非"去水印"**:
   - 抖音:`video.bit_rate[].play_addr.url_list` 按码率取最高(Evil0ctal/f2/TikTokDownloader 一致);`download_addr` 是烧录水印版,全部弃用;经典 `playwm→play` 字符串替换法在现行实现中已无踪迹(未核实现网是否仍可用,不推荐依赖)。
   - 快手:`mp4Url`/`photoUrl`(干净流)。
   - 小红书:`originVideoKey` 优先,`media.stream` 各档次之;图片去 `!` 后缀处理参数。
   - B站:DASH 音视频分轨 + ffmpeg 合流(无水印是天然的)。
   - **通用教训**:所有头部项目都选择"平台已发布的干净流",并接受"若作品只有水印流则只能拿到水印版"(Evil0ctal FAQ 原话)。
4. **直链下载**:CDN URL 带签名时效(Evil0ctal 归档 600s 后重解析);下载要带 UA/Referer;断点续传(XHS-Downloader)、自动跳已下载(XHS/KS)、SQLite 去重(jiji262)。

### 4.2 各家实现差异与可靠性对比

| 维度 | Evil0ctal v5 | f2 | TikTokDownloader(DouK) | XHS-Downloader | KS-Downloader | MediaCrawler |
|---|---|---|---|---|---|---|
| 平台 | 抖音/TikTok | 抖音/TikTok/微博/Twitter | 抖音/TikTok | 小红书 | 快手 | 小红书/抖音/快手/B站/微博+ |
| 签名方式 | 原生 Python(ab+secsdk+X-Gnarly)+浏览器漂移检测 | 原生 Python(xb/ab+假/真 msToken+ttwid) | 内置(移植 Evil0ctal)**已停止维护→插件制** | **无签名**(SSR+指纹) | 无签名(游客接口+指纹) | 浏览器 JS 出签 + xhshow 纯算 + wbi |
| 设备伪装 | wreq(TLS 模拟) | httpx(UA/cookie 层) | curl_cffi impersonate | curl_cffi impersonate | curl_cffi impersonate | 真机 Chrome/CDP |
| 风控治理 | 身份池+令牌桶+熔断(最强) | 无(单 cookie 直连) | 延时+代理 | 无(靠 cookie+慢速) | 延时+代理 | 登录态+代理池 |
| 服务化形态 | REST+MCP+CLI+控制台 | CLI+API | CLI/服务器模式(6.0 出 GUI/WebUI) | GUI/TUI/CLI/API/MCP | GUI/CLI | CLI(+FastAPI WebUI) |
| License | Apache-2.0(可商用) | Apache-2.0(可商用) | GPL-3.0 | GPL-3.0 | GPL-3.0 | NCAL(禁商用) |
| 主要失效模式 | 签名算法漂移(有探测器) | 签名算法漂移(靠作者) | 平台改版→需用户自备签名代码 | SSR 改版/无 cookie 低清 | 快手接口改版 | 浏览器环境/签名库漂移 |

**可靠性直觉排序(仅"贴链接→无水印直链"场景,2026-09 时点)**:
- 抖音:**Evil0ctal v5 ≈ jiji262 > f2 > TikTokDownloader(用户需自备签名) > MediaCrawler(需浏览器) > 页面解析系(已失效)**。
- 小红书:**XHS-Downloader(SSR,零签名维护)与 MediaCrawler xhs 模块(API+纯算)双路线并存**;纯 API 服务化更推荐 xhshow/RedCrack 类纯算 + cookie 池。
- 快手:**KS-Downloader(无签名游客接口)为最省维护路线**;接口失效后备为 MediaCrawler 式浏览器出签。
- B站:自研成本低(wbi+DASH 是公开接口),知识库虽被律师函关停但 fork/镜像与 MediaCrawler 代码仍在;注意法务合规。
- 西瓜:**无成熟开源,需自研页面解析**(老项目停更,细节未核实)。

### 4.3 给"全平台视频下载网站"的选型建议(调研结论)

1. **服务端 API 底座**:优先 **Evil0ctal v5**(Apache-2.0、REST API、身份池治理)承接抖音/TikTok;其"平台适配层"设计(签名实现+参数构造+归一化解析+端点策略)可作为新平台接入的模板。
2. **小红书**:采用 **SSR 解析路线(XHS-Downloader 思路)** 自研服务化版本——x-s/x-t 零维护成本,配合 cookie 池换高清;备选纯算签名库(xhshow/RedCrack)。
3. **快手**:采用 **KS-Downloader 的无签名游客接口**,加 cookie(did)池与代理。
4. **B站**:自研 wbi + DASH 合流(ffmpeg),公开接口、成本可控;注意合规。
5. **西瓜**:自研页面解析,或首期用商业 API(TikHub)兜底。
6. **工程红线**:①每条链路都要做"直链过期重解析"缓存策略(参照 Evil0ctal 600s);②引入身份池/令牌桶思想(单 IP 直连批量必被封);③TLS 指纹模拟(curl_cffi/wreq)是标配;④法律层面:B 站律师函先例 + MediaCrawler 禁用商用 + DouK 停止维护签名算法,说明**"内置逆向签名+对外服务"法律风险最高,选 Apache-2.0 且自托管形态、把签名做成可插拔/由第三方提供,是当前社区的主流避险姿势**。
