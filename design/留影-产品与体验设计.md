# 留影 · 分享链接视频保存工具

版本：概念设计 v1.1 · 2026-09-27；视觉方向按用户要求调整为 Apple 官网风格。

交付范围：产品需求、交互规范、视觉规范、分期计划，以及对话内可交互原型。本轮没有实现或部署真实解析、下载、账号连接及画面修复服务。原型的作品、画质、大小、任务和平台状态均为演示数据。

## 1. 产品决策

产品暂名「留影」，英文工作名 LIUYING。核心承诺：**粘贴分享链接，优先保存平台提供的无水印视频。**

用户可以提交任意分享文本，系统负责识别；实际下载能力由平台、作品权限、网络条件和当前解析器共同决定。「任何视频必定可下、任何水印无损消除」无法作为验收条件。

产品分两层能力：

| 能力 | 用户得到什么 | 默认行为 | 适用范围 |
|---|---|---|---|
| 无水印源下载 | 平台提供的未添加平台水印的媒体流 | 优先推荐；原样下载或无重编码合流 | 该作品确实存在、且当前可访问的流 |
| 画面水印修复 | 对已经压进像素的水印区域进行裁切、覆盖或模型修复 | 后续独立入口；先预览再导出 | 用户自有或获授权素材；可能损伤细节或出现闪烁 |

“原流”不等于作者上传母版。“无平台水印”不保证作者在画面中添加的 logo、字幕、台标也不存在。1080p/4K 必须来自实际格式清单，不做伪高清或自动放大。

先按中文用户、移动端访问优先、小规模公开试用的场景设计；架构同时支持个人自托管。收费、团队协作和第三方商用解析服务暂不接入。

## 2. 为谁解决什么问题

首要用户是保存自己跨平台作品的创作者、整理获授权素材的剪辑师，以及保存公开可下载内容的个人用户。

核心任务只有一件：从一段分享文案，得到能正常播放、画质可知、来源可追溯的文件。首版的价值排序为：下载成功且有声音 > 文件版本选对 > 少操作 > 多平台数量。

衡量指标：

- 主指标：符合当前支持范围的任务中，媒体校验通过且文件交付可用的比例。
- 并列记录全量提交结果，不能靠排除大量失败来美化成功率。
- 辅助指标：解析 P50/P95、文件就绪耗时、下载交付错误率、用户重试次数、每成功文件成本。
- 区分“服务器文件就绪”“已发起浏览器下载”“用户确认已保存”；普通浏览器下载不能证明用户设备已落盘。
- 画质与水印指标按平台、访问方式、解析器版本分组；不把解析成功等同于无水印成功。

## 3. 范围与接入顺序

下表是开发优先级，**不是现网可用性声明**。每个平台必须通过技术方案中的真实样本验收后才显示为支持。

| 批次 | 平台/内容 | 范围 | 上线条件 |
|---|---|---|---|
| 验证批 | 抖音、快手、小红书、B站 | 各抽样验证公开视频、短链、画质和原流 | 产出版本化样本结果，决定是否进入首发 |
| 首发候选 | 上述通过验收的平台 | 单作品视频、分享文案、选择画质、下载、重试 | 单个平台不达标就保留“内测”，不拖累其他平台 |
| 第二批 | TikTok、YouTube、Instagram、X；小红书/抖音图集 | 先单作品；图集再打包 | 补齐相应网络环境和媒体格式验收 |
| 第二批 | 每次最多 20 个链接、音频导出、历史去重 | 每条独立状态，可仅重试失败项 | 批量限额、容量预算和取消功能完成 |
| 后续探索 | 西瓜、视频号、更多站点、画面水印修复 | 每个平台单独调研与验收 | 不用“其他 1700+ 站”替代实际测试 |

首版排除：整站搜索、主页批量采集、直播录制、付费/DRM 解密、自动代过验证码、后台订阅抓取、公众 Cookie 共享池。源站要求额外访问权限时解释原因，不把技术故障伪装成付费解锁。

## 4. 信息架构

| 页面 | 核心内容 | 出现时机 |
|---|---|---|
| 下载 `/` | 分享输入、结果卡、画质选择、主要下载动作 | 默认首页 |
| 下载任务 `/tasks` | 处理中、可保存、失败、过期；单项取消/重试 | 存在任务时显示数量 |
| 平台状态 `/platforms` | 已验收范围、当前异常、最近一次检查及样本范围 | 用户想知道某平台是否可用 |
| 偏好 `/settings` | 默认画质、文件命名、历史清理 | 次级菜单 |
| 连接管理 `/connections` | 未来的个人访问连接、有效期、撤销 | 平台需要且已有受支持的连接方式时 |
| 运营后台 `/admin` | 解析器版本、失败分类、容量、恢复与回滚 | 仅运营人员；不进入用户主导航 |

匿名会话可完成公开内容的单次下载。账号只在需要跨设备历史、批量额度或个人连接时引入，不放在首次解析前。

## 5. 主流程

### 5.1 输入

首页主标题：「好视频。值得留住。」以两行居中显示，第二行用中性灰降低层级。

副标题：「一段分享链接，留住喜欢的片刻。优先获取无水印版本，保留源画质。」

输入标签：「视频分享链接」；占位文案：「粘贴链接，或直接粘贴整段分享文案」。唯一强调按钮：「解析链接」。

- 支持 Ctrl/⌘ + Enter 提交；Enter 保持文本框正常换行。
- 不监听系统剪贴板。正式产品的“粘贴”按钮仅在主动点击时读取，权限失败则提示手动粘贴。
- 提取多个链接时显示识别数量；首版让用户选择一个，批量版本列出清单。
- 保留分享链接中影响访问的参数，尤其平台令牌；日志另行脱敏，不在输入阶段全部删参数。
- 提交前可纠正空值和明显格式错误；未知站点不返回虚假的作品预览。

### 5.2 解析中

在结果区域显示“正在识别链接 / 正在获取视频信息 / 正在检查可用版本”。显示阶段即可，不编造百分比。输入保留，解析可取消。

设计目标：点击后 100ms 内进入反馈态；超出 8 秒提供“仍在获取，请稍候”的反馈；解析总超时预算初值 30 秒，实际依平台调优。

### 5.3 结果卡

桌面布局：左侧封面；右侧标题、作者、来源平台、时长、水印状态、画质和动作。手机上下堆叠，不让用户横向滚动。

信息优先级：

1. 标题 + 作者 + 平台，保留返回原作品的入口。
2. “平台无水印源 / 带水印 / 水印情况未知”的明确状态。
3. 可选择的真实画质、编码/容器、是否含声音、文件大小或“大小待确认”。
4. 推荐档位默认“最佳兼容”：优先可播放且有音频；高码率原始编码另列为可选档。
5. 主按钮写明动作，例如“保存无水印版本”；旁边可展开更多格式。

存在水印状态不同的格式时，选中格式决定标签和主按钮。用户切换到更高清的带水印档位，必须看见状态变化。没有干净源时不静默退回带水印文件。

### 5.4 准备与保存

默认后台准备完整文件，过程显示“排队 / 获取视频 / 合并音视频 / 文件就绪”。只有总字节数可信时显示下载百分比、速度、预计剩余时间。

文件就绪后出现「保存到设备」，展示大小和到期时间。浏览器开始下载后写“已发起下载”，不能仅靠按钮点击宣称“保存成功”。可再次保存同一未过期产物，避免重复消耗上游。

移动浏览器按能力使用常规下载或系统分享保存；不承诺所有浏览器都直接写入系统相册。下载后提供“找不到文件？”的简短浏览器说明。

### 5.5 失败也是主流程的一部分

| 情况 | 给用户的说明 | 下一步 |
|---|---|---|
| 分享链接不完整 | 没有识别到完整链接 | 保留输入，重新粘贴 |
| 内容删除/不可见 | 原作品目前无法访问 | 打开原作品核实；不无限重试 |
| 需要本人登录 | 当前只能获取公开版本，高清版本需要你的访问权限 | 保存当前可用版本；受支持时再连接个人账号 |
| 暂无干净源 | 这条作品目前只找到带水印版本 | 明确选择保存带水印版；后续可选画面修复 |
| 水印未知 | 可以保存，但暂时无法确认画面中的水印 | 查看预览并自行决定 |
| 平台临时异常 | 平台目前解析不稳定，请稍后重试 | 保留任务；显示可重试时间 |
| 短链/分享令牌失效 | 分享链接可能已过期 | 从原平台重新分享 |
| 文件链接失效 | 文件已过期，可重新准备 | 在后台重解析一次，失败再提示 |
| 当前未支持 | 已识别来源，但暂未开放下载 | 明确平台；保留原链接 |

小红书“无 Cookie 低清”是研究快照中的行为，不写死为永久规则：界面根据本次真正拿到的版本显示可下载档位。

## 6. 视觉方向

方向：参考 [Apple 中国官网](https://www.apple.com.cn/)及 [MacBook Air 产品页](https://www.apple.com.cn/macbook-air/)的排版、留白和配色，保持留影自己的名称、内容和操作流程。用纯白、浅灰与深灰建立层次；蓝色集中在主要动作和文字链接。首屏居中大标题，导航压缩为文字链接，结果区采用浅灰背景上的白色内容面板。

2026-09-27 实际读取参考页样式：正文 `rgb(29,29,31)`，页面背景 `rgb(255,255,255)`，主要购买按钮 `rgb(0,113,227)`，胶囊圆角。以下为留影的应用规范，深色方案、字号和间距是针对本产品的设计选择。

| 项目 | 规范 |
|---|---|
| 品牌 | 留影 / LIUYING；名称为工作名，尚未做商标或域名核验 |
| 浅色 | 页面 `#FFFFFF`；分区 `#F5F5F7`；文字 `#1D1D1F`；次级文字 `#6E6E73` |
| 深色 | 页面 `#000000`；分区 `#161617`；卡片 `#1D1D1F`；文字 `#F5F5F7`；次级文字 `#A1A1A6` |
| 强调色 | 浅色主按钮 `#0071E3` + 白字；链接 `#0066CC`；深色主按钮 `#0A84FF`、链接 `#2997FF` |
| 字体 | 系统无衬线优先，中文 PingFang SC 回退；正常正文 400 字重，标题 600；不下载 Apple 专有字体 |
| 字级 | 正文 14–16px，字段 16px；桌面主标题 58px，手机 42px；必要小注释 11–12px |
| 间距 | 顶部主视觉留白 58px；输入区最大 720px；结果区最大 860px；边距随屏宽缩小 |
| 圆角 | 输入框 18px，结果卡 24px，格式选项 12px，主按钮胶囊形；状态标签以文字呈现 |
| 动效 | 120–180ms 的状态变化；尊重 reduced-motion；无循环装饰动画 |
| 响应式 | 320/390/768/1024/1440px；内容不足时自然高度，不强制一屏 |
| 可访问性 | 操作区至少 44px；保留焦点样式；状态同时用文字表达；键盘可完成主链路 |

原型可切换经典蓝 / 石墨黑主要操作及页面疏密；默认采用经典蓝。结果卡保留五种演示状态；旧版本松绿/陶土偏好不会覆盖本次视觉方向。它用于确认信息层级和行为，不代表已实现相应服务。

## 7. 功能优先级与验收

| 优先级 | 需求 | 可观察验收结果 |
|---|---|---|
| P0 | 整段分享文本识别 | 常见中文标点、短链、重复链接不产生错误任务 |
| P0 | 格式预览 | 选中档位对应真实文件；无音轨不能假装有声音 |
| P0 | 无水印优先 | 有证据才标记无平台水印；回退格式重新判断 |
| P0 | 准备、下载、取消、重试 | 取消后停止上游工作；刷新可恢复会话任务 |
| P0 | 失效恢复 | 过期链接可重新解析；新流不误拼接旧分片 |
| P0 | 移动适配 | 小屏无溢出；系统下载流程可理解 |
| P0 | 平台能力状态 | 显示最近测试时间和范围；运营可单独停用坏适配器 |
| P1 | 图集、音频、20 链批量 | 独立选项；批量单项失败不导致全批作废 |
| P1 | 历史、个人连接 | 可删除记录和凭据；跨用户内容不可互见 |
| P2 | 水印画面修复 | 先预览 3–5 秒；显示耗时、费用及画质变化后再处理整段 |

画面修复的具体产品链路：选择已有文件或已准备的视频 → 框选水印及时间段 → 根据遮挡、运动情况选择裁切或修复 → 生成短预览 → 前后对比 → 确认整段导出。模型候选应使用自有样片比较边缘稳定性、时序闪烁、细节损失与单位分钟成本后确定；本轮不预选未经验证的模型。

## 8. 实施顺序与工作量假设

以下是排期假设，不是交付承诺。按 1 名前端、1 名后端、共享 QA/设计，以及平台调试能够正常开展估算：

| 阶段 | 预计工作日 | 必须交付 | 决策关口 |
|---|---:|---|---|
| 0：可行性验证 | 3–5 | 四个平台的真实样本包、解析/下载结果、版本锁定 | 首发平台名单基于结果确定 |
| 1：纵向闭环 | 5–7 | 一个通过验证的平台贯通输入到真实文件交付 | 文件可播、有声、状态准确 |
| 2：平台扩展 | 5–8 | 其余通过验证的平台、画质、失败恢复、任务列表 | 分平台验收完成 |
| 3：试用准备 | 3–5 | 手机端、容量限制、运营状态、回归和回滚 | 小范围试用，而非大规模承诺 |

总计约 16–25 个工作日的团队日历估计；遇平台接口变更、访问环境限制或独立适配工作增量要重新估算。画面修复、账号连接和商业化不计入这段时间。

首发以验证使用频率和下载完成率为目的。后续若收费，围绕批量、计算时间、存储、团队管理等真实成本设计额度，不售卖“绕过平台权限”。具体价格等成本和使用数据出来后再定。
