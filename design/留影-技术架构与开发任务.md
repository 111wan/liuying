# 留影 · 技术架构与开发任务

设计日期：2026-09-27。本文为拟实施架构，非已实现能力。平台路径参考工作区源码快照与上游文档，尚未在本项目做真实分享链接下载测试。

## 1. 核心选型

采用“统一产品 API + 可替换平台适配器 + 独立下载工作进程”。MVP 保持一个代码仓库和模块化服务，不拆一套庞大的微服务。

| 部分 | 首版决定 | 原因 |
|---|---|---|
| Web | React + TypeScript + Vite；自建轻量组件与 CSS 变量 | 输入、任务与格式选择是主要交互；方便独立调试 |
| API | Python + FastAPI | 便于衔接 Python 下载与解析生态 |
| 元数据 | PostgreSQL | 会话归属、任务状态、幂等约束、事件序号一致存储 |
| 队列 | Celery + Redis | 独立解析队列与下载队列；可靠状态留在 PostgreSQL |
| 主引擎 | yt-dlp 独立 worker 进程，锁定版本 | 对已验收的通用平台复用提取器；避免阻塞 API 事件循环 |
| 抖音 / TikTok | Evil0ctal v5 独立服务，内部鉴权接入 | 接入它的归一化能力；不直接把其管理 API 暴露给公众 |
| 快手 / 小红书 | 自有适配层，先验证研究中的简化路径 | 便于单平台停用、测试、替换；不整仓导入爬虫 |
| 媒体处理 | FFmpeg/ffprobe 独立受限进程 | 下载后校验、合流、转封装；尽量避免重编码 |
| 临时产物 | 开发用任务目录，公开试用用私有对象存储 | 文件寿命与任务寿命独立；支持大文件和 Range |
| 更新 | 明确版本 + 固定样本回归 + 灰度 + 回滚 | 可解释某个任务为什么在某一版本失败 |

依赖的具体版本在实现阶段通过兼容性测试锁定。YouTube 等提取路径需要的 JS runtime / EJS 组件也纳入镜像与版本清单，不能只安装 yt-dlp 就默认完备。[yt-dlp 官方说明](https://github.com/yt-dlp/yt-dlp)

起步容量仅作压测配置：应用/普通 worker 4 vCPU、8GB，浏览器型适配服务单独给资源；每平台解析并发初值 1–2，下载 worker 并发 2。实际按 CPU、峰值内存、源站响应和出口带宽调整，不据此宣称固定吞吐。

## 2. 请求路径与模块边界

数据路径：浏览器提交分享文案 → API 建立解析任务 → 安全链接展开 → 平台适配器 → 标准化格式清单 → 用户选择 → 下载任务 → 拉流/合流/校验 → 临时产物 → 浏览器保存。

模块职责：

- `input`：提取 URL、保留必要查询参数、规范化展示；不执行远程页面中的代码。
- `resolver`：展开短链，限制跳数，对每跳地址执行网络策略。
- `adapters`：仅产出标准化描述和私有流引用；不决定前端文案或用户额度。
- `format_policy`：选清晰度、兼容性、音轨、容器；分别记录水印状态，不因更高码率覆盖用户选择。
- `jobs`：归属、幂等、状态迁移、取消、可重试分类、预算、事件。
- `media_worker`：取有效流、限制大小/时长/时间、重试、合流、校验、产物提交。
- `delivery`：短效下载授权、断点请求、文件寿命、过期重建。
- `operations`：版本、平台能力、探针结果、熔断、降级、灰度。

持久化任务和 outbox 事件在同一事务提交，派发器再送队列。worker 使用租约、心跳和原子条件更新；重复投递不创建第二份产物，不重复扣减额度。

## 3. 平台路由

| 平台 | 第一候选路径 | 可选替代 | 上线前必须验证 |
|---|---|---|---|
| 抖音 | Evil0ctal v5 的平台详情与格式输出 | 独立验证后的其他实现；不默认 fallback 到旧 SSR | 短链、干净流标记、带水印回退、过期刷新、风控分类 |
| TikTok | 同一服务的 TikTok 适配器 | 通过样本集的 yt-dlp 路径 | 独立网络环境、地区可用性、画质和格式 |
| 快手 | 研究快照中的游客详情路径 | 待验证的其他适配器 | 接口方法/参数、did 生命周期、photoId/principalId 组合、CDN 可下载性 |
| 小红书 | 分享原链接 → SSR 状态数据 → 原片候选/各档媒体流 | 通过验收的 yt-dlp 或其他独立路径 | 保留 xsec_token、SSR 缺失、匿名与个人会话差异、回退流的水印状态 |
| B站 | yt-dlp；按实际权限列出 DASH/其他格式 | 经验证后加入 yutto | b23 短链、P 分集、音视频合流、清晰度权限、上传画面自带水印 |

| 西瓜 / 视频号 | 仅识别来源，暂不宣称支持 | 待专项验证 | 不能沿用停更项目参数假定可用 |
| 其他站点 | 默认提示尚未开放；测试通过后登记能力 | 专用受限长尾 worker 可后续引入 | 禁止直接把 generic extractor 变成无限制公网抓取入口 |

源码证据（相对工作区）：

- `research/extracted/JoeanAmier__XHS-Downloader/source/application/video.py`：`originVideoKey` 优先，然后从 `video.media.stream` 选择其他媒体地址；该选择不等同于所有回退流无水印。
- `research/extracted/JoeanAmier__KS-Downloader/source/request/detail.py`：`/live_api/profile/feedbyid`、`photoId` 与 `principalId`。具体 HTTP 行为还依赖基类，不能仅凭接口名推断。
- `research/extracted/Evil0ctal__Douyin_TikTok_Download_API/documents/zh/17-faq.md`：v5 的平台边界及无水印流条件。
- [yt-dlp 支持列表](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)：提取器存在不保证站点可用。

这些是代码/文档核对，**不是本轮现网下载实测**。用户研究中提及的 star 数、历史事件和性能数字不进入产品 SLA。

fallback 只处理明确可恢复的解析失败，最多一个额外候选并受整体 30 秒预算约束。登录、私密、删除、权限不足不通过切换身份反复尝试。连续平台级失败应熔断；新建身份不能解决平台接口整体变化。

## 4. 标准化数据模型

`MediaDescriptor` 至少包含：`id / platform / media_id / canonical_url / title / author / cover_ref / duration_ms / content_type / formats / resolved_at / adapter_version / access_scope`。

`Format` 至少包含：

```json
{
  "id": "fmt_opaque_01",
  "width": 1080,
  "height": 1920,
  "container": "mp4",
  "video_codec": "h264",
  "audio_codec": "aac",
  "has_audio": true,
  "size_bytes": null,
  "size_kind": "unknown",
  "watermark": {
    "platform_overlay": "absent",
    "embedded_mark": "unknown",
    "evidence": "adapter_source_metadata"
  },
  "requires_mux": false,
  "requires_transcode": false,
  "availability": "available"
}
```

此对象是协议示例。`platform_overlay` 枚举 `absent | present | unknown`，`embedded_mark` 同理。只有有根据的源标记才能给出 `absent`；没有字段不自动推断。界面使用“平台无水印源”，并在详情解释画面内原有文字/标志可能保留。

大小必须区分 `exact | estimated | unknown`；没有证据不显示虚构 MB。媒体内部 URL、Cookie、签名、必要请求头只留在 server-side `StreamRef`。前端只持有不透明格式 ID。

缓存键至少包含平台、作品 ID、分集、访问范围、会话/凭据版本、地区和适配器版本。用户凭据访问到的元数据/流不可跨用户复用。共享缓存仅限明确的公开内容；原始分享 token 不写入分析日志。

元数据缓存初值 5 分钟；流 URL 优先使用实际到期时间，并保留安全余量。未知有效期时在下载前重取。不能把所有平台固定写成“10 分钟必定有效”。

## 5. 公共 API 契约

| 方法与路径 | 请求/返回要点 |
|---|---|
| `POST /api/v1/resolutions` | `{text}`；返回 `202 {job_id, status_url, events_url}`；重复提交支持 Idempotency-Key |
| `GET /api/v1/jobs/{id}` | 归属校验后的当前快照、阶段、结果或规范化错误 |
| `GET /api/v1/jobs/{id}/events` | SSE，带单调事件 ID；Last-Event-ID 恢复；保留期外先给快照 |
| `GET /api/v1/media/{id}` | 归属校验后的元数据与可用格式，不返回上游 Cookie/签名 |
| `POST /api/v1/downloads` | `{media_id, format_id, output_profile}`；创建受限下载任务 |
| `POST /api/v1/jobs/{id}/cancel` | 幂等取消；传播到 worker 子进程并清理半成品 |
| `POST /api/v1/jobs/{id}/retry` | 建立新 attempt；校验预算、冷却和错误类型 |
| `POST /api/v1/artifacts/{id}/download-ticket` | 检查归属与有效期；生成短效文件交付链接 |
| `GET /api/v1/platforms` | 开放范围、功能状态、测试时间、当前异常；无样本就标“尚未验证” |

匿名用户也获得不可猜测的会话身份；任务 ID 本身不是授权。SSE 使用同源 HttpOnly 会话，不把长期凭据塞入 query 参数。跨站请求有相应 CSRF 控制。

SSE 事件示例：

```json
{
  "id": 17,
  "job_id": "job_example",
  "attempt": 1,
  "stage": "fetching",
  "received_bytes": 12582912,
  "total_bytes": null,
  "speed_bps": 2097152,
  "eta_seconds": null
}
```

首版默认“完整临时文件后交付”，保持恢复与状态简单。平台直链交付和服务端 tunnel 作为后续优化，仅在 Referer/Range/内容长度/跨域下载行为经过验证后启用。

## 6. 状态机与恢复

解析：`queued → resolving → ready`，或 `action_required / failed / cancelled`。

下载：`queued → fetching → muxing（按需）→ verifying → ready`，或 `failed / cancelled`；产物独立状态 `ready → expired`。

用户点击文件保存记 `download_requested` 事件。除非浏览器能力提供可信证据，否则不增加 `device_saved` 状态。

| 错误码 | 自动处理 | 用户操作 |
|---|---|---|
| `INVALID_INPUT` / `UNSUPPORTED` | 不重试 | 修改链接 / 查看支持范围 |
| `AUTH_REQUIRED` / `ACCESS_DENIED` | 不轮换别人的账号来尝试 | 使用自己的受支持连接或选公开版本 |
| `NOT_FOUND` | 不反复重试 | 核实原作品 |
| `RATE_LIMITED` | 尊重 Retry-After；单平台冷却 | 到时重试 |
| `UPSTREAM_CHANGED` | 熔断受影响适配器；保留任务 | 等待恢复后手动重试 |
| `SOURCE_EXPIRED` | 最多重解析一次 | 仍失败时重新分享 |
| `NETWORK_TIMEOUT` | 在任务预算内指数退避，初值最多 2 次 | 重试或取消 |
| `MEDIA_INVALID` | 不交付残缺文件，保留诊断 | 重试或换可用格式 |
| `LIMIT_EXCEEDED` | 停止拉流，释放配额保留 | 换小文件或更低档位 |

续传需要验证 ETag/Last-Modified/总长度或等效资源版本；重新解析得到的流与旧资源不一致就重新下载，不能把两个版本的字节拼在一起。请求完成、取消、失败和过期都要释放租约与容量预留。

## 7. 任意 URL 输入的网络边界

这部分是下载器必须实现的请求控制，不增加普通用户操作步骤。

- 初次 URL、每次重定向、媒体清单、嵌套清单、分片、字幕、封面和 HLS 密钥请求都经过相同策略。仅检查入口短链不够。
- 只接受允许的 HTTP(S) 目标；拒绝 URL 内 userinfo、文件协议、私网、loopback、链路本地、云元数据及 IPv6 等价地址。限制端口与重定向次数。
- 域名规范化、DNS 解析和实际连接目标共同验证；防止 DNS rebinding 与检查后目标变化。防止跨域重定向携带 Cookie/Authorization。
- 隔离 worker 出网代理/网络命名空间，从网络层拒绝内网。FFmpeg 优先读取已校验并落盘的媒体，不直接接收用户可控 URL。
- generic extractor、浏览器回退、第三方引擎必须走同样的出网边界，不能因适配器单独起进程就默认安全。
- SSR 状态数据用安全解析器，绝不 `eval`；子进程参数用数组，禁止拼接 shell；不开放任意 yt-dlp 参数输入。
- 文件名由服务器清理路径符和控制字符，输出路径绑定任务目录；时长、字节、分片数、CPU、内存、整体超时有硬限制。
- 生产私有凭据分用户加密，日志屏蔽 Cookie、完整 token URL；默认不记录原始分享文案。用户连接可撤销，凭据按源域限定。

## 8. 下载质量与容量

优先保持源编码；兼容档有 H.264/AAC 时直接复用，无需转码。只有用户选择且预算允许时转码到兼容格式，明确提示处理时间与可能的损失。音视频轨不能仅按码率任意配对，要核对时间线、语言、音轨权限和容器兼容性。

首版媒体校验：文件非空、ffprobe 可读、预期音视频轨存在、尺寸和时长合理、下载无缺失分片、合流退出码正确。端到端样本进一步做完整解码抽检与人工开头/中段/末尾画面检查；自动水印检测不能作为唯一“无水印”证明。

限额初值（产品配置，可调）：单文件 500MB、单视频 30 分钟、每匿名会话 1 个活跃下载任务；第二期批量每批 20 条。界面在可能时预先提示，后端拉流时仍执行硬限制。

临时产物初值保留 1 小时，下载 ticket 5 分钟，可在产物有效期内重新申请。服务端支持 Range；ticket 应允许同一授权范围内的正常重连，不能“一次性销毁”造成续传失败。删除记录不等于瞬时物理擦除，删除与 TTL 清理需有后台完成状态。

成本模型（非供应商报价）：

`单成功任务成本 = 出站 GB × 单价 + 临时 GB·小时 × 单价 + 计算时长成本 + 全部失败尝试分摊 + 可选第三方调用费`。

示例假设：平均 80MB，10,000 次成功交付约产生 800GB 十进制出站流量，未含重试、封面、预览与重复保存。若连续全天均匀分布且保留 1 小时，平均临时占用约 33GB，峰值和重试需额外容量。通过原流下载/无重编码合流控制 CPU；不能只看服务器月租。

## 9. 验收与发布门槛

每个平台先建立不少于 20 条可用公开视频的固定样本集，覆盖短链/长链、横竖屏、多画质、有无音轨、不同发布日期；另建立删除、私密、过期、受限、未知水印等负向用例。样本使用自有或允许测试的作品。

首发候选要求：在目标部署环境中，固定公开样本至少 19/20 完成解析、拉流和可播放文件交付；关键负向用例分类正确。这个小样本通过率只是工程门槛，不是对全网 95% 可用性的统计保证。展示真实样本数量、观察窗口和访问条件。

必须包含以下集成验证：

1. 两个用户互访任务/产物被拒，私人会话不命中别人缓存。
2. 重复点击、队列重复投递、worker 重启不生成重复任务产物或扣费。
3. SSE 断线后恢复，事件不倒序，刷新页面得到相同终态。
4. 过期 URL 重解析后格式状态重新核对，水印回退必须由用户明确选择。
5. 音视频分离文件合并后有声且同步；内容长度未知时前端不出现假进度。
6. 取消、限额、超时能终止子进程并清理临时占用。
7. 重定向与媒体分片指向内网、DNS rebinding、恶意文件名、异常 SSR 均被阻止。
8. 手机浏览器完成保存操作，不把发起下载当作落盘确认。

运维按平台/适配器版本统计，区分用户输入错误、源站权限、平台异常、我方容量问题。新解析器版本先跑固定样本、再小流量灰度；失败率达到阈值停用该版本并回滚。每日小规模探针只测自有样本，探针时间显示为“最近检查”，不包装成实时全站保证。
